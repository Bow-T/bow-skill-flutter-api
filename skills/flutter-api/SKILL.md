# flutter-api — thêm/sửa endpoint REST đúng khuôn

Khuôn thường gặp của app Flutter nói chuyện với backend REST riêng:

```
VM (BaseViewModel) ──api.xServices?.method()──► ApiClient: MỘT Dio + interceptor
                                                  │ gắn Bearer token + header Language
                                                  │ 401 → xoá phiên, về màn Signin
                                                  │ lỗi → DioException(message = MÃ lỗi server)
                                                  ▼
                              retrofit @RestApi → BaseResponse<T> | BaseResponse<Pagination<T>>
```

## 0. Đọc trước khi viết (bắt buộc)

Tên file dưới đây là khuôn tham chiếu. Repo lệch khuôn thì **theo repo**, đừng ép về khuôn này.

| Việc | File |
|---|---|
| Dio, interceptor, danh sách service | `lib/src/services/remote/api_client.dart` |
| Vỏ response | `remote/response/base_response.dart`, `remote/utils/pagination.dart` |
| Mã lỗi server → chữ | `remote/code_error.dart` + `lib/src/l10n/intl_*.arb` |
| Service cùng domain | `remote/<domain>_services.dart` |
| Body request | `remote/body/*_body.dart` |
| Model + converter | `lib/src/models/*_model.dart`, `lib/src/utils/utilities.dart` |
| VM gốc | `lib/src/base/base_vm.dart` |

Tên endpoint, tên tham số, kiểu `data` lấy từ Swagger/Postman/code backend — **không đoán**.
Quy ước đặt tên lấy theo backend, không theo "chuẩn REST" chung — vd backend .NET hay dùng query PascalCase
(`PageIndex`) nhưng JSON camelCase (`routineIds`); chép đúng như backend khai.

## 1. Thêm endpoint — theo thứ tự

**1. Model response** (`lib/src/models/x_model.dart`) — chỉ khi chưa có model dùng lại được:

```dart
part 'x_model.g.dart';

@JsonSerializable(includeIfNull: false, explicitToJson: true)
class XModel {
  @JsonKey(name: 'id')
  String? id;

  @JsonKey(name: 'createdDate', fromJson: Utilities.fromJsonDate, toJson: Utilities.toJsonDate)
  DateTime? createdDate;

  @JsonKey(name: 'tags', defaultValue: [])
  List<TagModel> tags = [];

  XModel();

  factory XModel.fromJson(Map<String, dynamic> json) => _$XModelFromJson(json);

  Map<String, dynamic> toJson() => _$XModelToJson(this);
}
```

- Mọi field có `@JsonKey(name:)` tường minh; scalar nullable; list non-null + `defaultValue: []`.
- Ngày, chuỗi đa ngôn ngữ (`{fr, en}`), duration đi qua converter có sẵn trong `Utilities` — đừng parse tay.
- Enum từ server PHẢI có đường lui, nếu không backend thêm một giá trị mới là hỏng parse CẢ response → màn trắng:
  enum `@JsonValue` → `@JsonKey(name: 'status', unknownEnumValue: XStatus.unknown)`;
  converter tự viết → `firstWhereOrNull` / `orElse` (`firstWhere` trần là sai).

**2. Body request** (`remote/body/x_body.dart`) — cùng annotation như model. Dựng bằng cascade;
ngày gửi đi dạng UTC ISO như các VM đang làm:

```dart
final body = ScheduleBody()
  ..routineIds = [routineId]
  ..date = date.toUtc().toIso8601String();
```

**3. Method trong service** — thêm vào service cùng domain, giữ khối doc-comment như các method bên cạnh:

```dart
@GET('api/routines/{id}')
Future<BaseResponse<RoutineModel>> getRoutine(@Path('id') String id);

@GET('api/routines')
Future<BaseResponse<Pagination<RoutineModel>>> getRoutines({
  @Query('Search') String? search,
  @Query('PageIndex') int? pageIndex,
  @Query('PageSize') int? pageSize,
});

@POST('api/schedules')
Future<BaseResponse<dynamic>> postSchedule({@Body() required ScheduleBody body});
```

- Luôn trả `BaseResponse<...>`; list có phân trang là `BaseResponse<Pagination<T>>`.
- `dynamic` chỉ khi server thật sự không trả `data` có nghĩa.
- Upload: `@MultiPart()` + `@Part() File file`; file lớn đi presigned S3 qua `StorageS3Uploader` có sẵn.

**4. Service mới** (domain mới hẳn): `remote/<domain>_services.dart` gồm `part '<domain>_services.g.dart';`,
`@RestApi()`, `factory XServices(Dio dio, {String baseUrl}) = _XServices;` → đăng ký trong `ApiClient`:
field `XServices? xServices;` + `xServices = XServices(dio, baseUrl: AppConstants.baseURL);`.
**Dùng `dio` của ApiClient** — Dio mới là mất token, Language, xử lý 401 và dịch lỗi.

**5. Mã lỗi server mới** (backend trả `"message": "SOME_CODE"`): hằng trong `code_error.dart` → `case`
trong `toLang` → key `errorCodeXxx` trong **MỌI** `intl_*.arb` (vd `intl_fr.arb` + `intl_en.arb`;
locale chính khai ở `flutter_intl.main_locale` trong `pubspec.yaml`). Thiếu một bước là người dùng thấy nguyên chuỗi `SOME_CODE`.

**6. Sinh code:**

```bash
fvm flutter pub run build_runner build --delete-conflicting-outputs   # .g.dart: model, body, service
fvm dart run intl_utils:generate                                       # khi sửa .arb
fvm flutter analyze
```

Repo không dùng fvm thì bỏ tiền tố `fvm`. KHÔNG sửa tay `*.g.dart`.

## 2. Gọi từ ViewModel

Theo kiểu file đang dùng — `.then/.catchError/.whenComplete` và `await` + `try / on DioException / finally`
là tương đương:

```dart
Future<void> save() async {
  isLoading = true;
  notifyListeners();
  api.scheduleServices?.postSchedule(body: body).then((response) {
    if (response.success) {
      showSuccess(response.message);
      eventBusSchedule.fire(true);          // màn khác cần làm mới
    } else {
      showError(response.message);          // đừng bỏ trống nhánh này
    }
  }).catchError((e) {
    final code = e is DioException ? e.message : null;
    if (code == trainingTimeFull) {         // so MÃ trước khi dịch
      onDailyFull?.call();
      return;
    }
    showError(code?.toLang ?? S.current.messageErrorProcessingFailed);
  }).whenComplete(() {
    isLoading = false;
    notifyListeners();
  });
}
```

- `response.message` đã dịch sẵn (getter gọi `toLang`). Lỗi vào `catchError` thì `e.message` là MÃ → phải `.toLang`.
- **Đừng** `onError.message as String` (kiểu đang có ở nhiều VM): lỗi không phải `DioException`
  (parse JSON hỏng, bug trong `.then`) hoặc `message == null` thì cast ném lần hai, người dùng không thấy gì.
- 401, mất mạng, 500 đã có interceptor lo — VM không tự xử lại, không tự điều hướng về Signin.
- Token/header do interceptor gắn — VM và service KHÔNG tự thêm `Authorization`.
- Thao tác chặn cả màn (submit) → `showLoading()` / `hideLoading()` (dialog); tải dữ liệu trong màn → cờ `isLoading`.
- Hàm submit mở đầu bằng `if (isLoading) return;` — bấm hai lần là hai request.
- KHÔNG gắn retry tự động (`RetryInterceptor`) vào Dio chính: POST bị timeout KHÔNG có nghĩa là thất bại
  (server có thể đã ghi), retry là tạo trùng lịch/đơn. Retry chỉ cho request idempotent (GET, PUT lên S3).

## 3. Danh sách phân trang (`infinite_scroll_pagination`)

```dart
static const _pageSize = AppConstants.pageSizeDefault;
final paging = PagingController<int, XModel>(firstPageKey: 1);   // PageIndex bắt đầu từ 1

XVm() {
  paging.addPageRequestListener(_fetchPage);
}

void _fetchPage(int pageKey) {
  api.xServices?.getXs(pageIndex: pageKey, pageSize: _pageSize).then((response) {
    if (!response.success) {
      paging.error = response.message;
      return;
    }
    final items = response.data?.items ?? [];
    if (items.length < _pageSize) {
      paging.appendLastPage(items);
    } else {
      paging.appendPage(items, pageKey + 1);
    }
  }).catchError((e) {
    paging.error = e;
  });
}

@override
void dispose() {
  paging.dispose();
  super.dispose();
}
```

- Đăng ký listener trong **constructor**. Widget phân trang xin trang 1 ngay trong `initState`
  (đồng bộ), còn `onInit` chạy sau frame đầu → đăng ký ở `onInit` là trượt trang 1.
- Đừng override `addListener` để đăng ký (kiểu hay gặp trong code cũ) — hàm đó chạy lại mỗi khi có listener mới ⇒ đăng ký trùng
  ⇒ gọi API trùng.
- Làm mới: `paging.refresh()`.

## 4. Làm mới chéo màn (EventBus) — phải huỷ

Kiểu hay gặp: `EventBus` toàn cục khai trong file VM (`eventBusSchedule`, `eventBusAppUser`…).
`listen()` trả `StreamSubscription` — **giữ lại, cancel trong `dispose`**. Không cancel thì VM đã đóng
vẫn nghe: mỗi lần mở lại màn thêm một listener, một sự kiện bắn N lần API.

```dart
StreamSubscription<bool>? _scheduleSub;

@override
void onInit() {
  _scheduleSub = eventBusSchedule.on<bool>().listen((_) => getSchedules());
}

@override
void dispose() {
  _scheduleSub?.cancel();
  super.dispose();
}
```

## 5. Cấm

| Đừng | Vì |
|---|---|
| `Dio()` mới để gọi API app | mất token/Language/401/dịch lỗi. Ngoại lệ duy nhất: PUT lên presigned S3 URL |
| `@Body() Map<String, dynamic>` cho endpoint MỚI; `json['key']` trong VM/widget | mất kiểu, sai tên field chỉ lộ lúc chạy. Map cũ (auth) để yên trừ khi đang sửa đúng endpoint đó |
| Sửa `*.g.dart` | build_runner ghi đè |
| Secret (key server, token quản trị) trong `.env*` | `.env*` được khai trong `flutter: assets:` ⇒ nằm nguyên văn trong APK/IPA. Chỉ để key PUBLIC phía client |
| Log token/body ngoài `kDebugMode` | lộ phiên trong log máy |
| Hardcode base URL | đi qua `AppConfig` theo flavor (`lib/app/main_{dev,stg,prod}.dart`) |

## 6. Trước khi báo xong
